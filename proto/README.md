# proto — 프로토타입 (게임 본편이 아니다)

여기 있는 것은 **시험용**이다. `index.html` 은 이 폴더를 한 줄도 안 부르고,
여기 있는 파일도 `game.js` 를 안 읽는다. 지워도 게임은 그대로 돈다.

```bash
npm start
# http://localhost:8080/proto/room3d.html
```

## room3d.html — 마이 룸 한 장면을 «종이 공작» 3D 로

「다이어터 연금술사를 셀 셰이딩 3D 로 만들 수 있나」에 대한 **답 대신 만든 것**이다.
말로 「됩니다/안 됩니다」 하는 것보다 **한 장면을 띄워 놓고 보는 쪽**이 정확하다.

결은 **페이퍼 마리오 + 돈 스타브**다 — 세트가 전부 «오려 낸 종이»이고, 3D 는
그 종이들을 **층으로 세워 시차를 주는** 일만 한다.

### 이 프로토타입이 답하는 질문 하나

> **방만 3D 로 바꾸고, 인물은 지금 그림 그대로 둘 수 있는가?**

그럴 수 있다. 여기서 도는 것이 그것이다 —
**방은 three.js, 인물은 `avatar.js` 가 만든 SVG 를 그대로 세운 «빌보드»**다.

왜 그게 중요한가: 캐릭터를 3D 로 다시 만들면 **옷 150벌 · 표정 서른여덟 ·
체형 다섯 · 크리처 서른**이 통째로 날아간다. 그건 「3D 로 바꾸는 일」이 아니라
**게임을 새로 만드는 일**이다. 방만 3D 로 두면 그 자산이 한 픽셀도 안 바뀐 채로
3D 공간 안에 선다 — 그리고 되돌리는 것도 폴더 하나를 지우는 일이다.

### 그림을 만드는 것은 three.js 가 아니라 «잉크와 종이» 한 덩어리다

파일 위쪽의 `PAL` · `inkStroke` · `paperShape` · `paperCard` 넷이 보이는 것을 다 만든다.
3D 쪽은 그 카드를 세우는 일만 한다 — **「더 예쁘게」는 저 넷을 고치는 일이다.**

- **잉크선은 «붓»이다** (`inkStroke`). 같은 굵기로 `stroke()` 하면 벡터 클립아트가 된다 —
  양 끝이 가늘고 가운데가 굵은 다각형을 직접 만들어 칠한다. 떨림은 **씨앗이 정한다**
  (매 프레임 새로 뽑으면 선이 지글거린다 — 돌깨기의 얼룩과 같은 규칙이다)
- **오려 낸 종이는 순서가 있다** (`paperShape`) — **재단면(크림 테) → 칠 → 아래 그늘 →
  잉크선**. ⚠️ 잉크를 «먼저» 그으면 재단면이 그 위를 덮어 테만 남는다
- ⚠️⚠️ **선 굵기는 «픽셀»이 아니라 «세상의 길이»다.** 카드마다 텍스처 해상도가 달라서
  (벽 1024px/9.6칸 · 책장 640px/2.6칸) 같은 숫자 5 가 화면에서 두 배 넘게 갈렸다.
  `tex(w, h, draw, { units })` 에 **그 카드가 세상에서 몇 칸인지**를 주면 저절로 맞는다
  · ⚠️ **그렇다고 못 박으면 «작은 카드»가 통째로 잉크가 된다** — 0.86칸짜리 촛대에서
    그 선이 카드 폭의 7% 라 등잔이 «덩어리»로 보였다. `PPU` 를 70~150 으로 자른다
- **카드는 살짝 휜다** (`paperCard` 의 `curl`). 평평한 판은 «스티커»로 보인다 —
  판을 여러 칸으로 나눠 z 를 사인으로 미는 한 줄이 「3D 안에 종이가 서 있다」를 만든다
- **접지 그림자가 없으면 종이가 공중에 뜬다** (`stand` 의 `shadow`)
- **셀 셰이딩** — `MeshToonMaterial` + **세 칸짜리 그라디언트 맵**.
  ⚠️ 보간을 끄지 않으면(`NearestFilter`) 그냥 부드러운 음영으로 되돌아간다.
  ⚠️ **칠에 이미 음영이 그려져 있으므로 램프를 부드럽게 둔다** — 여기서 빛까지 세게
  끊으면 그림이 탁해진다
- **외곽선용 «뒤집힌 껍질»은 없앴다** — 잉크가 이제 텍스처에 «그려져» 있다.
  껍질은 두께가 물체 기준이라 종이 카드에서는 테만 굵어지고 손맛이 안 난다
- **무늬는 캔버스에 직접 그린다** — 마룻널·돌벽 이음새·창밖 하늘·책장의 기운 책들.
  외부 이미지가 하나도 없다
- **분위기 셋** — 안개(`THREE.Fog`) · 빛줄기 속에 떠오르는 먼지 90점 ·
  CSS 비네트와 필름 그레인. ⚠️ **벽 밑동과 천장 쪽이 어두워야 방이 «상자»로 읽힌다**
- **인물** — `Avatar.build()` → SVG → 캔버스 → `CanvasTexture` → 세로축 빌보드.
  ⚠️ 판의 크기와 자리는 **뷰박스와 `bodyMetrics().floorY` 를 읽어서** 맞춘다.
  숫자를 박으면 몸무게·바디파츠를 바꾸는 순간 인물이 바닥을 뚫거나 뜬다
- **크리처도 빌보드다** — `Creature.draw()` 를 그대로 세운다.
  **어디에 서는지는 `move` 가 정한다**(게임과 같은 규칙) — 물고기는 어항 ·
  날개가 있으면 공중 · 나머지는 땅. 세이브에 애착 크리처가 있으면 그 아이가 땅에 선다
  · ⚠️ **어항은 «같은 상자 안»에 겹쳐 세운다** (`creature.js` 의 그 규칙 그대로) —
    유리통(뒤) → 물고기 → 테·반사(앞). 물고기만 그룹 «안»에서 헤엄치므로
    유리 너머로 보인다 (한 장으로 합치면 물고기가 유리 위에 얹힌다)
  · ⚠️ **바닥 그림자는 빌보드가 아니다** — 누워 있는 판이라 그룹을 따라 돌면
    타원이 바닥에서 빙글빙글 돈다. 그룹이 돈 만큼 되돌린다
  · ⚠️ **공중에 뜬 아이도 바닥에 그림자가 진다** — 없으면 어디쯤 떠 있는지가 안 읽힌다
  · ⚠️ 바꿀 때 **옛 그룹을 통째로 버린다** — 안 지우면 같은 자리에 겹쳐 쌓인다
    (삼각형 수가 안 느는 것으로 확인한다)
- **발밑 그림자** — 빌보드는 그림자를 못 만든다. 없으면 인물이 바닥에서 «뜬다»
  · ⚠️⚠️ **빌보드는 «빛도» 안 받는다**(`MeshBasicMaterial`) — 그것이 맞는 선택이다
    (SVG 에 이미 음영이 있고, 판이 늘 카메라를 보므로 어차피 평면광이 된다).
    그런데 그냥 두면 **밤이 되어도 인물만 대낮**이라 방에서 혼자 떠 보인다 —
    그려 보고 알았다. `material.color` 로 달빛을 곱한다(`TINT`).
    ⚠️ **새로 만드는 판도 «지금 색»을 물고 나와야 한다** — 밤에 옷을 갈아입으면
    그 판만 대낮으로 되돌아간다. 양탄자도 같은 재질이라 같이 물들인다
- 낮/밤 · 자동 회전 · **📐 펼쳐 보기**(카드를 앞뒤로 벌려 「종이 층」을 보여 준다) ·
  옷 바꾸기 · 크리처 바꾸기 · 몸무게 · 바디파츠

세이브가 있으면 **그 사람의 옷을 그대로 입고 선다**(`dieter_alchemist_save_v1`).

### 그리다 두 번 헛짚은 자리 (되돌리지 말 것)

- ⚠️ **붙박이 카드를 옆벽에 세우면 «모서리»만 보인다.** 촛대 셋을 옆벽에 90° 로
  세웠더니 화면에 하나도 안 나왔다 — 등불은 켜져 있는데 등잔이 없는 방이었다.
  빌보드가 아닌 것은 **뒷벽에 붙인다** (종이 극장에서 보이는 것은 뒷벽 한 장이다)
- ⚠️ **앞쪽 «무대 앞막» 카드는 시야 밖이었다.** 화각 32°·거리 11.6 에서 z=4.7 짜리
  판은 한 프레임도 안 보인다. 깊이를 만드는 것은 앞에 뭘 세우는 것이 아니라
  **벽 밑동이 어두워지는 것**이라, 바닥에 깐 그늘 띠로 바꿨다

### 알아 둘 것

- ⚠️⚠️ **게임 파일(`data.js`·`avatar.js`·`creature.js`)은 «열 때마다» 새로 받는다.**
  서버가 정적 파일에 1년짜리 캐시를 주고 본편은 `index.html` 의 `?v=` 로 그것을 넘기는데,
  여기서 그냥 `<script src="../avatar.js">` 로 두면 **그림을 고쳐도 옛 파일이 계속 온다.**
  프로토타입에 캐시 버스터를 «또» 적으면 본편과 어긋나는 사본이 하나 더 생기므로,
  시각(`?t=`)을 붙여 캐시를 아예 안 쓴다 (프로토타입이라 그래도 된다)
- **three.js 를 `vendor/` 에 넣어 두었다**(0.160.0 · MIT · 라이선스 머리말 그대로).
  CDN 을 안 쓰는 이유 둘 — 배포 환경에서 바깥으로 못 나가는 경우가 있고,
  **검사기가 확인할 수 없는 의존은 이 저장소의 규칙에 안 맞는다**
- 여기는 **검사기가 안 돈다.** `checkui`·`checkavatar` 는 게임 화면만 본다 —
  프로토타입이라 그것이 맞지만, **여기 있는 것을 본편으로 옮길 때는 검사부터 만든다**
- 성능은 실제 기기에서 봐야 한다. 이 저장소의 헤드리스 검사는 소프트웨어 렌더라
  fps 가 낮게 나온다 (조각 3천 개짜리 방이다)

### 여기서 본편으로 가려면 (순서)

1. **마이 룸만** 3D 로 (지금 이것) — 인물·크리처는 빌보드 ✅
2. 방 꾸미기를 3D 소품으로 (`ROOM_LEVELS` 의 id 가 그대로 쓰인다)
3. 채집지·마을을 같은 방식으로 — **화면마다 하나씩**. 한꺼번에 바꾸면 되돌릴 데가 없다
4. 인물을 3D 로 바꾸는 것은 **맨 마지막에, 따로 정할 일**이다 (옷 150벌이 걸려 있다)
